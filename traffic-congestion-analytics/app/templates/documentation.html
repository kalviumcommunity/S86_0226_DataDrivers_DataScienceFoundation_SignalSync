API Documentation

Complete reference for developers and integrations

Getting Started

The Traffic Congestion Analytics API provides RESTful endpoints for accessing traffic data, predictions, and analytics. All endpoints return JSON responses.

Base URL: http://localhost:5000

Dataset Configuration

Select the dataset you want to use for API requests and predictions. The selected dataset will be used for all analytics and prediction endpoints.

Dataset Active

Using: Metro Interstate Traffic Volume Dataset

All API endpoints are active with real traffic data from the Metro Interstate dataset.

File Size: 3.8 MB
Status: Active

API Endpoints

GET

/api/summary

Retrieve complete traffic summary statistics and congestion data.

Response Example:
{
  "status": "success",
  "data": {
    "summary": {
      "total_records": 48613,
      "avg_traffic_volume": 3259.82,
      "peak_hour": 17,
      "busiest_day": "Friday"
    },
    "congestion": {
      "overall_congestion_rate": 35.2,
      "hourly_congestion": {...}
    }
  }
}
GET

/api/predict

Predict traffic volume based on input parameters.

Query Parameters:
  • hour (required) - Hour of day (0-23)
  • weather (optional) - Weather condition (Clear, Rain, Snow, Clouds, Mist)
  • temp (optional) - Temperature in Kelvin (default: 280)
  • weekday (optional) - Day of week (0=Monday, 6=Sunday)
  • month (optional) - Month (1-12)
Example Request:
GET /api/predict?hour=17&weather=Rain&temp=285&weekday=4
Response Example:
{
  "status": "success",
  "data": {
    "predicted_volume": 4523.45,
    "is_congested": true,
    "congestion_threshold": 4000,
    "input_features": {
      "hour": 17,
      "weather": "Rain",
      "temp": 285,
      "weekday": 4,
      "month": 1
    }
  }
}
GET

/api/analytics/{type}

Get specific analytics type.

Available Types:
  • peak_hours - Peak traffic hours analysis
  • weather_impact - Weather impact statistics
  • monthly_trends - Monthly traffic trends
  • bottlenecks - Traffic bottleneck identification
Example Request:
GET /api/analytics/peak_hours

Error Handling

All API endpoints return standard HTTP status codes:

  • 200 Success - Request completed successfully
  • 400 Bad Request - Invalid parameters
  • 404 Not Found - Resource not found
  • 500 Server Error - Internal server error
Error Response Example:
{
  "status": "error",
  "message": "Missing required parameter: hour"
}
